## IMPLEMENTED: atomic lease renewal

Previously `renew_lease` read a Job and wrote back the entire snapshot. A separate
process completing or reclaiming the job in between could have its state
overwritten; an intervening checkpoint could also disappear. Audit insertion
failure left the new clock visible without a matching audit event.

Renewal now updates only `claimed_at` and `updated_at`, conditional on RUNNING
status, attempt, provider and observed claim clock. Clock and audit insertion
share one SQLite transaction. A changed claim is refused with ValueError. Existing
call signature, schema and dependencies are preserved.

This protects the database read-to-write interleaving. It does NOT authenticate
the actor, nor reject an old worker that calls the job-id-only API after a new
attempt has already started. A future attempt-bearing API and generic
submission/failure-path review remain open. This is not a distributed lock proof.
